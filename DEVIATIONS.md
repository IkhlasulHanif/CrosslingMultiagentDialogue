# DEVIATIONS

Every departure from GOALS.md: one line + reason.

- **Model = `IFM/K2-Horizon-375B-A23B`.** Largest K2 Horizon in the fleet, and per docs.ifm.ai the only size served on the hosted API (`https://api.ifm.ai/v1`).
- **`USD_PER_M_IN = USD_PER_M_OUT = 0.0`.** docs.ifm.ai publishes no per-token price: the API is a free pre-GA preview, and the binding limit is **10,000,000 tokens/day per key** (resets at 00:00 UTC). With zero prices, `BudgetExceeded` never fires. The runner therefore pauses new games once the day's logged tokens exceed 9.4M, and resumes after the reset. `make cost` reports tokens alongside the USD meter. The human may set real prices, and `BUDGET_USD` is untouched.
- **Reasoning field name.** The hosted API returns the trace in `message.reasoning` (the documented mirror field), not in `reasoning_content`. The engine reads `reasoning_content` if present, otherwise `reasoning`, and replays it as `reasoning_content` (the docs say either is accepted). S0 confirmed the replay through prompt-token growth (seller turn 3 prompt = turn-1 prompt + turn-1 completion + opponent reply).
- **Upstream is read, not executed.** The sandbox policy refused to execute code fetched from GitHub. `arena_plus/protocol.py` reproduces the upstream buy-sell prompt template, goal strings, constants and tag parser. `tests/test_upstream_fidelity.py` checks the template and constants character-for-character against the pinned upstream files (read as text). Upstream stays untouched at `vendor/NegotiationArena` (submodule, commit c447faf).
- **REJECT ends the game.** Upstream `AlternatingGameEndsOnTag` ends only on ACCEPT, although its own prompt says "The game will end if one of the players ACCEPT OR REJECT". Right-or-wrong outcomes need walking away to be real, so the prompt's rule is followed.
- **Answer normalisation = upstream semantics.** Upstream only tests `answer == "ACCEPT"`, so any other answer that carries a trade (e.g. `PROPOSE`) is a proposal. My first parser was stricter and voided S0 seed 2. That record was dropped and seed 2 re-played.
- **Format failures.** A reply without a parseable answer/trade, or ACCEPT with no standing opponent proposal, is re-sampled on the same history (up to 3 tries, all attempts logged). After 3 failures the game is `void`: it is counted and excluded from the metrics. Truncated replies (`finish_reason == "length"`) are handled the same way and never parsed.
- **Smoke games are the first 5 seeds of the run.** `make smoke RUN=x N=5` plays seeds 1–5 of run x; the full run resumes at seed 6 with an identical config (same config hash). This saves duplicated games under the daily token cap.
- **Branch `grounded-arena`, not `main`.** The working tree arrived with the previous project deleted (~6k files). Committing that deletion to `main` is left to the human; all grounded-arena work is pushed to this branch.
- **`logs/` stays gitignored** (pre-existing rule). Per-run token usage is copied into `runs/<run>/summary.json`, so it is committed.
- **Leak detector.** A leak is the seat's own private number in its visible `<message>`, with a value word within 60 characters: seller words cost/produce/paid/floor/minimum/…, buyer words budget/at most/maximum/willing/worth/value/…. It is regex plus number match only (§5), which misses paraphrases like "a bit over sixty".
- **Client-side rate limiter.** The hosted API also enforces an unpublished per-minute request guard (429 "Request rate limit exceeded"). Observed throughput was about 15 calls/min. `arena_plus/ratelimit.py` caps started calls at `K2_RPM` (default 15) per rolling 60 s across all processes, before every `k2.chat`. This does not change the model inputs.
- **One diagnostic call outside `k2.py`** (S1, while diagnosing the 429s): a raw-response probe to read rate-limit headers. It was itself rejected with 429 and consumed no tokens. It is not repeated, and every model call goes through `k2.chat`.
